블록 정렬, 열 개로 한 걸음씩

무작위 숫자 10개가 정렬되는 과정을 한 단계씩 따라간다. 보고서 2.3절의 구현(src/blockSort.c)과 같은 순서로 돈다.

시작 — 0 / 0

왼쪽 런 · 블록 오른쪽 런 정렬 끝난 구간 지금 회전할 구간 비교 0 · 이동 0

무슨 일이 벌어지고 있나

1단계 — 블록마다 삽입 정렬

배열을 작은 블록으로 자르고, 블록 하나씩 삽입 정렬한다. 짧은 배열에서는 삽입 정렬이 제일 빠르다.

이 단계가 끝나면 정렬된 조각 여러 개가 늘어서 있다.

2단계 — 이웃한 조각을 병합

이웃한 두 조각을 하나로 합치고, 합친 폭을 두 배로 넓혀 다시 합친다. 폭이 배열 전체가 되면 끝이다.

병합 정렬과 같은 뼈대인데, 보조 배열을 쓰지 않는다는 점이 다르다.

도구는 회전 하나뿐

보조 배열이 없으니 원소 덩어리를 회전으로 옮긴다. 회전은 뒤집기 세 번이면 된다. 추가 메모리가 필요 없다.

(A B C)(D E)
① 앞쪽 뒤집기 → (C B A)(D E)
② 뒷쪽 뒤집기 → (C B A)(E D)
③ 전체 뒤집기 → (D E)(A B C)

제자리 병합이 도는 방법

정렬된 두 런 L과 R을 보조 배열 없이 합쳐야 한다. 한 번에 다 하려 들지 않고, 원소 하나의 자리를 확정하고 문제를 둘로 쪼갠다.

  1. L의 마지막이 R의 첫 원소 이하면 이어 붙이면 끝이다. 할 일 없음.
  2. 아니면 긴 쪽의 한가운데 원소를 고른다.
  3. 반대쪽에서 그 원소가 들어갈 자리를 이분 탐색으로 찾는다.
  4. 사이 구간을 회전시킨다. 고른 원소의 자리가 확정된다.
  5. 왼쪽에 남은 짝과 오른쪽에 남은 짝을 같은 방법으로 다시 합친다.

한가운데를 어느 쪽에서 골랐느냐에 따라 이분 탐색의 종류가 갈린다. 왼쪽에서 골랐으면 lowerBound(그 값 이상이 처음 나오는 자리), 오른쪽에서 골랐으면 upperBound(그 값 초과가 처음 나오는 자리)다. 같은 값일 때 왼쪽 것이 앞에 남게 하려는 것이고, 이 선택 하나가 안정성을 지킨다.

블록 크기에 대하여. src/blockSort.c는 블록 크기를 ceil(√n)으로 잡되 하한을 16으로 둔다. 너무 잘게 자르면 병합만 늘어나기 때문이다. 그래서 실제 코드에서 n = 10이면 배열 전체가 블록 하나가 되고, 삽입 정렬 한 번으로 끝나 병합이 아예 일어나지 않는다. 여기서는 구조를 보여 주려고 블록 크기를 직접 고르게 했다. 위 선택 상자를 2에서 5까지 바꿔 보면, 블록을 잘게 자를수록 병합 단계가 길어지는 것이 보인다.
