블록 정렬, 한 걸음씩

무작위 숫자가 정렬되는 과정을 한 단계씩 따라간다. 블록 크기까지 보고서 2.3절의 구현(src/blockSort.c)과 같은 값을 쓴다.

무슨 일이 벌어지고 있나

1단계 — 블록마다 삽입 정렬

병합을 하려면 정렬된 조각이 먼저 있어야 한다. 병합 정렬은 재귀로 쪼개 만들고, 블록 정렬은 작은 블록을 삽입 정렬해 만든다. 짧은 배열에서는 삽입 정렬이 제일 빠르기 때문이다.

그래서 1단계는 준비 운동일 뿐이다. 블록 정렬다운 일은 2단계에서 벌어진다.

2단계 — 이웃한 조각을 병합

이웃한 두 조각을 하나로 합치고, 합친 폭을 두 배로 넓혀 다시 합친다. 폭이 배열 전체가 되면 끝이다.

병합 정렬과 같은 뼈대인데, 보조 배열을 쓰지 않는다는 점이 다르다.

왜 뒤집기를 세 번 하나

보조 배열이 있으면 한쪽을 복사해 두고 밀면 된다. 그것이 없으니 두 덩어리를 제자리에서 통째로 맞바꿔야 한다.

(A B C)(D E)
① 앞쪽 뒤집기 → (C B A)(D E)
② 뒷쪽 뒤집기 → (C B A)(E D)
③ 전체 뒤집기 → (D E)(A B C)

뒤집기는 두 번 하면 제자리다. 둘을 각각 뒤집어 둔 뒤 전체를 한 번 더 뒤집으면, 각 덩어리는 두 번 뒤집혀 순서가 돌아오고 덩어리끼리의 앞뒤만 바뀐다. 중간 ①②가 엉망으로 보이는 것은 정상이다. ③까지 가야 뜻이 생긴다.

제자리 병합이 도는 방법

정렬된 두 런 L과 R을 보조 배열 없이 합쳐야 한다. 한 번에 다 하려 들지 않고, 원소 하나의 자리를 확정하고 문제를 둘로 쪼갠다.

  1. L의 마지막이 R의 첫 원소 이하면 이어 붙이면 끝이다. 할 일 없음.
  2. 아니면 긴 쪽의 한가운데 원소를 고른다.
  3. 반대쪽에서 그 원소가 들어갈 자리를 이분 탐색으로 찾는다.
  4. 사이 구간을 회전시킨다. 고른 원소의 자리가 확정된다.
  5. 왼쪽에 남은 짝과 오른쪽에 남은 짝을 같은 방법으로 다시 합친다.

한가운데를 어느 쪽에서 골랐느냐에 따라 이분 탐색의 종류가 갈린다. 왼쪽에서 골랐으면 lowerBound(그 값 이상이 처음 나오는 자리), 오른쪽에서 골랐으면 upperBound(그 값 초과가 처음 나오는 자리)다. 같은 값일 때 왼쪽 것이 앞에 남게 하려는 것이고, 이 선택 하나가 안정성을 지킨다.

왜 원소가 40개부터인가. src/blockSort.c는 블록 크기를 32 상수로 쓴다(blockSortBlockSize). 그래서 원소가 32개 이하면 배열 전체가 블록 하나가 되어, 삽입 정렬 한 번으로 끝나고 병합이 아예 일어나지 않는다. 블록 정렬이 블록 정렬답게 도는 것을 보려면 원소가 33개 이상이어야 한다. 기본값 40은 병합이 도는 것 중 가장 짧은 축이고, 96으로 올리면 폭을 두 배로 넓히는 두 번째 병합까지 돈다. 1단계는 2단계로 ⏩로 건너뛸 수 있다.

블록 크기가 n을 따라가지 않고 상수인 이유는 보고서의 블록 크기는 얼마가 좋은가에서 재 보았다. 블록을 키우면 1단계 비용이 O(n·B)로 정비례해 늘고, 아껴지는 병합 비용은 log 수준으로만 준다. 그래서 최적값은 n과 무관한 작은 상수다.
